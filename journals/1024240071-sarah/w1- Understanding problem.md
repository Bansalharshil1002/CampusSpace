# Week 1 -- Sarah (Frontend)

## Understanding the Problem Statement & Planning

### Work Done

-   Studied the Room Status Tracker problem statement with the team.
-   Focused on understanding what information the frontend would need to
    display to users.
-   Identified the main screens and user interactions required by the
    application.
-   Discussed how room status, room type, user role, and assignments
    would be represented in the interface.
-   Helped divide the project into frontend and backend
    responsibilities.
-   Coordinated with the backend pair to understand the information that
    would be required from the backend.

### Key Observations

The frontend needs to present room information clearly while adapting
available actions according to the user's role and permissions.

### Issues Faced

-   It was initially difficult to determine the exact interface
    requirements before the backend data structure was finalized.
-   We needed to understand how different user roles would affect what
    users could see or do.
-   Coordination with the backend team was required to establish a
    common data flow.

### Outcome

The frontend requirements and basic interface plan were established,
providing a foundation for development in Week 2.
