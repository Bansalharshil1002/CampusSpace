## Understanding the Problem Statement & Planning

### Work Done

-   Reviewed the Room Status Tracker problem statement with the team.
-   Focused on understanding the data and operations required on the
    backend.
-   Identified the need for separate functionality for users, rooms,
    assignments, and room statuses.
-   Discussed how different roles would interact with rooms.
-   Helped plan the database-related requirements and backend service

### Key Observations

The system requires permission checks so that users can update only the
rooms they are allowed to manage. Status history also needs to be
maintained instead of simply replacing the previous status.

### Issues Faced

-   Some requirements were initially ambiguous and needed to be
    discussed as a team.
-   We had to determine how room types, user roles, and assignments
    would be related.
-   Planning the interaction between frontend, backend, and database
    required additional clarification.

### Outcome

The team completed the initial planning stage and established a clear
direction for backend development.
