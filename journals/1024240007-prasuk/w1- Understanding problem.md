# Week 1 -- Prasuk (Backend)

## Understanding the Problem Statement & Planning

### Work Done

-   Studied the Room Status Tracker problem statement and discussed the
    expected functionality with the team.
-   Focused on understanding the backend requirements and what
    information the system would need to store.
-   Identified the main backend entities: users, rooms, room
    assignments, and room statuses.
-   Discussed different user roles such as student, CR, teacher, admin,
    and society representative.
-   Helped plan the backend structure and divide the project into
    separate services.
-   Worked with Harshil on defining the initial backend responsibilities
    and how they would connect with the frontend.

### Key Observations

The backend would need to do more than store room information. It would
also need to handle permissions, assignments, status updates, and status
history.

### Issues Faced

-   The problem statement initially required discussion to understand
    the exact scope of the application.
-   It was initially difficult to decide which functionality should
    belong to the backend and which should be handled by the frontend.
-   Understanding how user roles and room assignments should affect
    permissions required additional discussion.

### Outcome

By the end of Week 1, the backend requirements were clearer and the team
had a basic plan for implementing the system.
